Lesson 00 · L0 · Setup

Infrastructure setup: project, packages, secrets, and the Testing ritual

★ No LLM

What you'll learn

You are building Claudalytics Copilot, a .NET agent that answers questions about LLM cost and ClickHouse telemetry. If you run every lesson with the default settings, each gate calls a real Claude model at full price and your secrets risk getting committed to git. This lesson sets up one boot command that pins every model to the cheap Haiku tier and loads your API key from a gitignored file, so every later lesson stays cheap, repeatable, and safe.

The scaffold you build here carries through all 19 lessons: the .csproj with exact package versions, the two-file appsettings split (base config + Testing overrides), the appsettings.Local.json gitignore pattern for your Anthropic API key, and the verification step every later gate depends on. Docker is deferred to the capstone (CAP); for now you run bare dotnet run.

📘 Teach

MAF projects depend on three packages that must be version-pinned together: Microsoft.Agents.AI, Microsoft.Agents.AI.Anthropic, and Microsoft.Agents.AI.Workflows. The Anthropic provider package is on a preview track and its suffix (-preview.YYMMDD.N) changes weekly — pinning it prevents silent upgrades that break the API. OpenTelemetry packages are pinned separately.

The Testing environment is not a test project. It is an ASP.NET named environment loaded by appsettings.Testing.json. You activate it by passing --environment Testing to the host at startup. It does two things in this curriculum. First, it overrides all three model tiers to claude-haiku-4-5, so every gate costs a fraction of a cent. Second, it raises the Microsoft.Agents.AI log namespace to Debug, which you need to observe compaction in E2. You use this environment for every lesson except one real-tier check in D3.

The -- separator matters. Without it, dotnet reads --environment Testing as its own flag, not as an argument to your program. The host then stays in Production with no error. E2 calls out this trap again. It is the most common reason a working compaction provider produces no Debug logs.

Build it

  1. Create the solution and web project

    The Copilot is a web service, so you start with an ASP.NET minimal-API project. Create a solution with one project targeting .NET 9. Use the project name AiAgent: all later lessons import types from the AiAgent.* namespace, so the name must match. 

    dotnet new sln -n Claudalytics
dotnet new web -n AiAgent -f net9.0
dotnet sln add AiAgent/AiAgent.csproj

  2. Pin packages in AiAgent.csproj

    The agent code in later lessons imports three MAF packages: Microsoft.Agents.AI (the agent runtime), Microsoft.Agents.AI.Anthropic (the Claude provider), and Microsoft.Agents.AI.Workflows (the multi-step workflow engine). The three OpenTelemetry packages send traces to ClickHouse so the Copilot can later read its own telemetry. Replace the generated AiAgent.csproj with the pinned versions below.

    AiAgent/AiAgent.csproj 
    <Project Sdk="Microsoft.NET.Sdk.Web">

  <PropertyGroup>
    <TargetFramework>net9.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <NoWarn>$(NoWarn);MAAI001;MEAI001</NoWarn>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="Microsoft.Agents.AI" Version="1.9.0" />
    <PackageReference Include="Microsoft.Agents.AI.Anthropic" Version="1.9.0-preview.260603.1" />
    <PackageReference Include="Microsoft.Agents.AI.Workflows" Version="1.9.0" />
    <PackageReference Include="OpenTelemetry.Exporter.OpenTelemetryProtocol" Version="1.15.3" />
    <PackageReference Include="OpenTelemetry.Extensions.Hosting" Version="1.15.3" />
    <PackageReference Include="OpenTelemetry.Instrumentation.AspNetCore" Version="1.15.2" />
  </ItemGroup>

</Project>

    The NoWarn line suppresses two build warnings, MAAI001 and MEAI001. Both are expected. The compaction and chat-reducer APIs are marked experimental in MAF 1.9.0 and M.E.AI 10.5. You use them in E2, so you suppress the warnings now to keep later lesson output clean.

    The Anthropic provider package is on a preview track. Its suffix (-preview.YYMMDD.N) changes every week. Pinning the exact version stops a silent upgrade from breaking the API. Then restore: 

    dotnet restore AiAgent/AiAgent.csproj

  3. Write the base appsettings.json

    This file holds non-secret configuration that is safe to commit: the listen URL, the log levels, and the three model tiers. A ModelTiers helper, added later in D3, reads the tier names (Light, Analyst, Reasoning). Every lesson that creates an agent reads its model name from this file.

    AiAgent/appsettings.json 
    {
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*",
  "Urls": "http://localhost:8124",
  "CLICKHOUSE_URL": "http://localhost:8123",
  "CLICKHOUSE_USER": "agent_ro",
  "Models": {
    "Light": "claude-haiku-4-5",
    "Analyst": "claude-sonnet-4-6",
    "Reasoning": "claude-opus-4-8"
  }
}

  4. Write appsettings.Testing.json

    This file is the cost and safety net for every lesson. It overrides all three tiers to Haiku and enables Debug-level logging for the MAF namespace. It is committed — it contains no secrets and must be predictable on every machine.

    AiAgent/appsettings.Testing.json 
    {
  "Models": {
    "Light": "claude-haiku-4-5",
    "Analyst": "claude-haiku-4-5",
    "Reasoning": "claude-haiku-4-5"
  },
  "Logging": {
    "LogLevel": {
      "Microsoft.Agents.AI": "Debug"
    }
  }
}

    Why Haiku for all three tiers? The tiers exist so that in production, a router turn uses a Light model and a deep-analysis turn uses Reasoning. In Testing you want all turns equally cheap — and equally observable — without changing any call sites. The override is total: any lesson code that reads config["Models:Reasoning"] gets Haiku in Testing.

  5. Create the gitignored secrets file

    Add appsettings.Local.json to .gitignore first, then create the file. Never reverse this order — the secrets file must not appear in git even for a moment. 

    # In the repo root .gitignore — add this line:
**/appsettings.Local.json

    Then create the file (do not commit it):

    AiAgent/appsettings.Local.json ← gitignored 
    {
  "ANTHROPIC_API_KEY": "sk-ant-…your-key-here…"
}

    The Anthropic provider package reads ANTHROPIC_API_KEY from configuration at startup. In Program.cs, load the secrets file last, after all other sources, so its key wins over any environment variable with the same name. Keep this file secrets-only: ANTHROPIC_API_KEY and an optional CLICKHOUSE_PASSWORD.

    AiAgent/Program.cs (excerpt — full file in step 6) 
    var builder = WebApplication.CreateBuilder(args);

builder.Configuration.AddJsonFile(
    "appsettings.Local.json", optional: true, reloadOnChange: true);

    The file is optional: true so CI does not fail when the file is absent. On a CI machine there is no local file. CI injects the key as an environment variable instead.

  6. Add a health endpoint and boot the app

    Add a minimal health endpoint so you have something to curl before any agents exist. This is the entire Program.cs for this lesson.

    AiAgent/Program.cs 
    var builder = WebApplication.CreateBuilder(args);

builder.Configuration.AddJsonFile(
    "appsettings.Local.json", optional: true, reloadOnChange: true);

var app = builder.Build();

app.MapGet("/healthz", () => Results.Ok(new { status = "ok" }));

app.Run();

    Now launch with the Testing environment flag:

    cd AiAgent
dotnet run -- --environment Testing

    The -- is not optional. It tells dotnet that everything after it is an argument to your program, not to the dotnet run command itself. Without it, --environment is parsed by dotnet, not by ASP.NET's host builder, and your process silently starts in the Production environment.

How the environment stack loads

ASP.NET loads configuration sources in this order, with each later source winning over earlier ones:

  1. appsettings.json — base values (committed)
  2. appsettings.{Environment}.json — environment overlay; in Testing this is appsettings.Testing.json (committed)
  3. Environment variables — CI injects secrets here
  4. appsettings.Local.json — developer secrets, loaded last (gitignored)

The result: on your machine the Anthropic API key comes from appsettings.Local.json; in CI it comes from an env var; in both cases the key wins over any prior source. Model tiers are overridden to Haiku by appsettings.Testing.json whenever the environment is Testing.

Verify

✅ Gate — do not advance until green

Green check 1 — environment confirmed in console output.

When you run dotnet run -- --environment Testing, the ASP.NET host writes its environment to the console during startup. Look for this line: 

info: Microsoft.Hosting.Lifetime[0]
      Hosting environment: Testing

If you see Production instead, you forgot the -- separator.

Green check 2 — health endpoint responds.

curl http://localhost:8124/healthz
# Expected: {"status":"ok"}

Negative test — the silent Production trap.

Run without the separator and observe the difference: 

# Wrong — dotnet consumes --environment Testing itself
dotnet run --environment Testing

# The console will print:
#   Hosting environment: Production
# appsettings.Testing.json is NOT loaded.
# All model tiers stay at the production values (Sonnet, Opus).
# Any gate that checks for Haiku spans will fail.

This is the most important negative test in the curriculum. Every lesson's Verify section assumes you are in Testing. If you are not, the Haiku-pinned cost guarantee is gone and Debug logs for compaction (E2) are suppressed.

ℹ️ Note

Docker is deferred. You run the backend directly with dotnet run throughout the curriculum. You will not need Docker until the capstone (CAP). Until then, run dotnet run -- --environment Testing directly; the ClickHouse URL in appsettings.json points to localhost for when you do have a local instance, but the setup lessons do not require it.

⚠️ Pitfalls
  • Console says Hosting environment: Production → you ran dotnet run --environment Testing without the -- separator. Dotnet consumed the flag; your program never saw it. Always: dotnet run -- --environment Testing.
  • Build error MAAI001 or MEAI001 → the NoWarn line is missing from .csproj. These are expected warnings for the experimental compaction API; suppress them now so they do not pollute lesson output in E2.
  • Restore fails or preview package not found → the Microsoft.Agents.AI.Anthropic version suffix is time-stamped (1.9.0-preview.260603.1). If NuGet cannot resolve it, check the NuGet listing for the latest 1.9.0-preview.* and update the version string. Pin to whatever you resolve; do not use * wildcards.
  • API key not found at runtime → confirm appsettings.Local.json exists in the project directory (next to AiAgent.csproj), not the solution root. AddJsonFile resolves relative to the content root, which is the project directory when running with dotnet run.
  • appsettings.Local.json appears in git status → the .gitignore entry was added after the file was already tracked. Run git rm --cached AiAgent/appsettings.Local.json to untrack it without deleting it, then commit the .gitignore change.
