第 08 课 · C1 · 模块 C — 打造产品

受护栏保护的 SQL + 结构化输出

★★ Haiku

你将学到什么

本课给智能体（agent）开放数据库访问权限，而这正是危险所在。一个自己写 SQL 的智能体可能跑 DROP TABLE otel_logs 毁掉遥测数据；可能无时间过滤地 扫描 otel_logs，读上百万行、跑好几分钟；它的自由文本回答也没法被代码 直接取出字段。C1 让数据库访问变安全，并让答案带类型。一个 SQL 校验器在任何查询执行前拒绝所有写入动词、强制时间范围；RunAsync<T> 把智能体的回答变成代码能直接读的带类型 C# record。

📘 讲解

受护栏保护的工具模式。智能体的 SQL 工具不直接调 ClickHouse， 先调 SqlValidator.Validate()：拒写入动词、对大表要求时间过滤、缺 LIMIT 就补。两道边界——数据库用户 agent_ro 是硬边界 （数据库本身拒写），校验器是软边界（用模型能读懂的错误信息提前失败）。

结构化输出（structured output）。 agent.RunAsync<T>() 强制模型返回符合 T 形状的 JSON。record 上的 Description 特性会进入发给模型的 schema，模型因此 知道每个字段的含义。

用到的具名 MAF API： AIAgent.RunAsync<T>(prompt, session) · AIAgent.CreateSessionAsync() · AgentResponse<T>.Result · AIFunctionFactory（注册 AnalysisTools，在 A1 已建立）。

为什么要分两个阶段？

调 RunAsync<T>() 时，MAF 会让模型在该次运行的每一轮都输出结构化 JSON——包括本该去请求数据的工具调用那一轮。结果是坏掉的循环：模型在没数据时硬填 CostBreakdownReport，JSON 要么为空要么是幻觉，工具根本没跑。

修复办法是在同一个 session 上分两阶段：

  1. 收集阶段——普通 RunAsync()，开工具。智能体调 CostBreakdown 拿到真实行数据。
  2. 报告阶段——RunAsync<CostBreakdownReport>()， 用指令关掉工具。智能体只对上下文里已有的数据做结构化。

session 是那座桥：第 1 阶段的原始数据留在对话历史里，第 2 阶段读它。

  1. 步骤 1 — 添加 SQL 校验器

    创建 Tools/SqlValidator.cs，这就是讲解里的软边界，每次查询前运行， 要么返回安全查询、要么抛一条智能体能据以改正的消息。第一段声明四个正则：要求开头是 SELECT/WITH、捕获写入和管理类关键字、检测 LIMIT、识别大表 otel_logs。

    Tools/SqlValidator.cs — 类与正则声明 
    using System.Text.RegularExpressions;

namespace AiAgent.Tools;

public static partial class SqlValidator
{
    private const int DefaultLimit = 100;

    [GeneratedRegex(@"^\s*(SELECT|WITH)\b", RegexOptions.IgnoreCase)]
    private static partial Regex SelectOrWith();

    [GeneratedRegex(@"\b(INSERT|UPDATE|DELETE|ALTER|DROP|CREATE|RENAME|TRUNCATE|ATTACH|DETACH|OPTIMIZE|GRANT|REVOKE|KILL|SYSTEM|FORMAT)\b|\bINTO\s+OUTFILE\b", RegexOptions.IgnoreCase)]
    private static partial Regex DeniedKeywords();

    [GeneratedRegex(@"\bLIMIT\s+\d", RegexOptions.IgnoreCase)]
    private static partial Regex HasLimit();

    [GeneratedRegex(@"\botel_logs\b", RegexOptions.IgnoreCase)]
    private static partial Regex TargetsOtelLogs();

    第二段是 Validate，按顺序检查：单语句、开头合法、无禁用关键字、命中 otel_logs 时要有 Timestamp 过滤。失败抛 ArgumentException，消息写给模型看；通过且无 LIMIT 就补一个再返回。 requireTimeFilter 默认 true，只有 C3 的无界工具会传 false。

    Tools/SqlValidator.cs — Validate（闭合类） 
        public static string Validate(string query, bool requireTimeFilter = true)
    {
        var sql = query.Trim().TrimEnd(';').Trim();

        if (sql.Contains(';'))
            throw new ArgumentException("Only a single SQL statement is allowed.");

        if (!SelectOrWith().IsMatch(sql))
            throw new ArgumentException("Only SELECT (or WITH ... SELECT) queries are allowed.");

        var denied = DeniedKeywords().Match(sql);
        if (denied.Success)
            throw new ArgumentException($"Keyword '{denied.Value}' is not allowed. This tool is read-only; FORMAT is appended automatically.");

        if (requireTimeFilter && TargetsOtelLogs().IsMatch(sql) && !sql.Contains("Timestamp", StringComparison.OrdinalIgnoreCase))
            throw new ArgumentException("Queries against otel_logs must filter on Timestamp (it is a large table). Add e.g. WHERE Timestamp >= now() - INTERVAL 1 DAY.");

        if (!HasLimit().IsMatch(sql))
            sql += $" LIMIT {DefaultLimit}";

        return sql;
    }
}

    using System.ComponentModel;
using AiAgent.Agents;

namespace AiAgent.Tools;

public sealed class SchemaTools(ClickHouseClient clickHouse)
{
    [Description("Returns the full ClickHouse schema reference: tables, columns, attribute extraction idioms and example queries.")]
    public string GetSchema() => Instructions.SchemaDoc;

    [Description("Executes a read-only SELECT query against the claudalytics ClickHouse database and returns rows as tab-separated text. Single statement only; otel_logs queries must filter on Timestamp; a LIMIT is added if missing.")]
    public async Task<string> RunSql(
        [Description("The SELECT (or WITH ... SELECT) query to execute.")] string query)
    {
        try
        {
            var sql = SqlValidator.Validate(query);
            return await clickHouse.QueryAsync(sql);
        }
        catch (Exception ex)
        {
            return $"QUERY FAILED: {ex.Message}";
        }
    }

    第二段加两个预置 list 工具。ListProjects 和 ListRecentSessions 对小表 sessions 跑固定查询，让智能体在 写关于某项目或会话的查询前先解析出真实 id，而不是瞎猜。

    Tools/SchemaTools.cs — ListProjects、ListRecentSessions（闭合类） 
        [Description("Lists all project names that have telemetry data, with session counts.")]
    public async Task<string> ListProjects()
    {
        try
        {
            return await clickHouse.QueryAsync(
                "SELECT project_name, count() AS sessions, max(last_event_at) AS latest_activity " +
                "FROM sessions FINAL GROUP BY project_name ORDER BY latest_activity DESC LIMIT 50");
        }
        catch (Exception ex)
        {
            return $"QUERY FAILED: {ex.Message}";
        }
    }

    [Description("Lists the most recent sessions, optionally filtered to one project.")]
    public async Task<string> ListRecentSessions(
        [Description("Optional project name to filter by; empty for all projects.")] string project = "")
    {
        try
        {
            var filter = string.IsNullOrWhiteSpace(project)
                ? ""
                : $"WHERE project_name = '{project.Replace("'", "''")}' ";
            return await clickHouse.QueryAsync(
                "SELECT session_id, project_name, started_at, last_event_at, otel_event_count " +
                $"FROM sessions FINAL {filter}ORDER BY last_event_at DESC LIMIT 20");
        }
        catch (Exception ex)
        {
            return $"QUERY FAILED: {ex.Message}";
        }
    }
}

  4. 步骤 4 — 添加预置的分析工具

    创建 Tools/AnalysisTools.cs：为最高价值的问题预写的已知正确查询， 省得模型每次现写 SQL。第一段是类和 CostBreakdown，构建最常见的 「按某维度看窗口内花费」查询，默认按 project 分组（工作区的主访问单元）。 它的结果就是 /analyze/cost 第 1 阶段要收集的原始数据。

    Tools/AnalysisTools.cs — 类与 CostBreakdown 
    using System.ComponentModel;

namespace AiAgent.Tools;

public sealed class AnalysisTools(ClickHouseClient clickHouse)
{
    [Description("Cost breakdown between two dates, grouped by model, project, session or day. Optionally restricted to one project. Returns cost and token sums per group, highest cost first.")]
    public async Task<string> CostBreakdown(
        [Description("Window start, ClickHouse-parseable, e.g. '2026-06-01' or 'now() - INTERVAL 7 DAY'. Quoted literals only when a date string.")] string start,
        [Description("Window end, e.g. 'now()'.")] string end,
        [Description("Grouping: one of model, project, session, day.")] string groupBy,
        [Description("Optional: restrict to one project name (exact project_name). Empty = all projects.")] string? project = null)
    {
        var groupExpr = groupBy.Trim().ToLowerInvariant() switch
        {
            "model"   => "LogAttributes['model']",
            "project" => "ResourceAttributes['project.name']",
            "session" => "LogAttributes['session.id']",
            "day"     => "toDate(Timestamp)",
            _         => null,
        };
        if (groupExpr is null)
            return "INVALID group_by: use model, project, session or day.";

        var projectFilter = string.IsNullOrWhiteSpace(project)
            ? ""
            : $"\n              AND ResourceAttributes['project.name'] = '{project.Replace("'", "''")}'";

        var sql = $"""
            SELECT {groupExpr} AS grp,
                   round(sum(toFloat64OrZero(LogAttributes['cost_usd'])), 4) AS cost_usd,
                   sum(toUInt64OrZero(LogAttributes['input_tokens'])) AS input_tokens,
                   sum(toUInt64OrZero(LogAttributes['output_tokens'])) AS output_tokens,
                   sum(toUInt64OrZero(LogAttributes['cache_read_tokens'])) AS cache_read_tokens,
                   count() AS api_requests
            FROM otel_logs
            WHERE LogAttributes['event.name'] = 'api_request'
              AND Timestamp >= {Expr(start)} AND Timestamp < {Expr(end)}{projectFilter}
            GROUP BY grp ORDER BY cost_usd DESC LIMIT 50
            """;
        return await RunValidated(sql);
    }

    第二段是 SessionDeepDive：对一个会话跑五条查询——总计、工具使用、 文件改动、被拦截工具、访问网站——拼成一个字符串，让模型一轮内读完整会话画像。

    Tools/AnalysisTools.cs — SessionDeepDive 
        [Description("Deep dive into one session: totals (cost, tokens, duration), tool usage, file mutations, blocked tools and visited sites.")]
    public async Task<string> SessionDeepDive(
        [Description("The session_id to analyze.")] string sessionId)
    {
        var id = sessionId.Replace("'", "''");

        var totals = await RunValidated($"""
            SELECT min(Timestamp) AS first_event, max(Timestamp) AS last_event,
                   round(sum(toFloat64OrZero(LogAttributes['cost_usd'])), 4) AS cost_usd,
                   sum(toUInt64OrZero(LogAttributes['input_tokens'])) AS input_tokens,
                   sum(toUInt64OrZero(LogAttributes['output_tokens'])) AS output_tokens,
                   countIf(LogAttributes['event.name'] = 'api_request') AS api_requests
            FROM otel_logs
            WHERE LogAttributes['session.id'] = '{id}' AND Timestamp >= now() - INTERVAL 90 DAY
            """);

        var tools = await RunValidated($"""
            SELECT LogAttributes['tool_name'] AS tool, count() AS calls,
                   countIf(LogAttributes['success'] = 'true') AS successes
            FROM otel_logs
            WHERE LogAttributes['event.name'] = 'tool_result'
              AND LogAttributes['session.id'] = '{id}' AND Timestamp >= now() - INTERVAL 90 DAY
            GROUP BY tool ORDER BY calls DESC LIMIT 20
            """);

        var mutations = await RunValidated(
            $"SELECT action, count() AS files FROM file_mutations WHERE session_id = '{id}' GROUP BY action ORDER BY files DESC LIMIT 10");

        var blocked = await RunValidated(
            $"SELECT tool_name, count() AS blocked FROM blocked_tools FINAL WHERE session_id = '{id}' AND completed = 0 GROUP BY tool_name LIMIT 10");

        var sites = await RunValidated(
            $"SELECT domain, count() AS visits FROM websites_visited WHERE session_id = '{id}' GROUP BY domain ORDER BY visits DESC LIMIT 10");

        return $"## Totals\n{totals}\n\n## Tool usage\n{tools}\n\n## File mutations\n{mutations}\n\n## Blocked tools\n{blocked}\n\n## Websites visited\n{sites}";
    }

    第三段是两个私有辅助。RunValidated 是上面两工具共用的 try/catch 包装：校验、执行、错误转文本。Expr 守护窗口边界： start/end 来自用户、需作 SQL 表达式求值（如 now() - INTERVAL 7 DAY），直接拼会有注入风险，所以只放行日期字面量和 简单 now()/today() 表达式，其余抛异常。

    Tools/AnalysisTools.cs — RunValidated 与 Expr（闭合类） 
        private async Task<string> RunValidated(string sql)
    {
        try
        {
            return await clickHouse.QueryAsync(SqlValidator.Validate(sql));
        }
        catch (Exception ex)
        {
            return $"QUERY FAILED: {ex.Message}";
        }
    }

    private static string Expr(string value)
    {
        var trimmed = value.Trim().Trim('\'');
        return System.Text.RegularExpressions.Regex.IsMatch(trimmed, @"^[\d\-: ]+$")
            ? $"'{trimmed}'"
            : System.Text.RegularExpressions.Regex.IsMatch(trimmed, @"^(now\(\)|today\(\)|yesterday\(\))(\s*[-+]\s*INTERVAL\s+\d+\s+(SECOND|MINUTE|HOUR|DAY|WEEK|MONTH))?$",
                System.Text.RegularExpressions.RegexOptions.IgnoreCase)
                ? trimmed
                : throw new ArgumentException($"'{value}' is not a date literal or a simple now()/today() expression.");
    }
}

    public const string SchemaDoc = """
        # Claudalytics ClickHouse schema (database: claudalytics, 90-day TTL)

        The data has TWO query surfaces. Prefer the small typed tables when they fit;
        use otel_logs only for cost/tokens/tool metrics and event types with no typed table.

        ## Surface 1 — otel_logs (LARGE, raw OpenTelemetry logs)
        Columns: Timestamp (DateTime64), LogAttributes (Map(String,String)),
        ResourceAttributes (Map(String,String)), Body, SeverityText.
        Attributes need map extraction, e.g.:
          LogAttributes['event.name']            -- event type
          ResourceAttributes['project.name']     -- project
          LogAttributes['session.id']            -- session
          toFloat64OrZero(LogAttributes['cost_usd'])
          toUInt64OrZero(LogAttributes['input_tokens'])   -- also output_tokens,
                                                          -- cache_read_tokens, cache_creation_tokens
        Key event.name values:
          'api_request'   -- one LLM call: cost_usd, input/output/cache tokens, model, duration_ms
          'user_prompt'   -- prompt_length, (prompt text if enabled)
          'tool_result'   -- tool_name, success ('true'/'false'), duration_ms, tool_parameters (JSON)
          'tool_decision' -- tool_name, decision (accept/reject), source
          'hooks.*'       -- 31 hook event types (hooks.PreToolUse, hooks.PostToolUse, ...)
        EVERY otel_logs query MUST filter on Timestamp (e.g. Timestamp >= now() - INTERVAL 7 DAY).

        ## Surface 2 — typed tables (small, pre-parsed; no map extraction needed)
        sessions(session_id, project_name, started_at, last_event_at, otel_event_count,
                 has_otel_data, has_hook_data)
          ENGINE ReplacingMergeTree -> ALWAYS query as: FROM sessions FINAL
        blocked_tools(timestamp, project_name, session_id, use_id, tool_name, tool_input, completed)
          ENGINE ReplacingMergeTree(completed) -> ALWAYS use FINAL;
          after FINAL, completed = 0 means the tool call was BLOCKED (denied).
        credential_exposures(timestamp, project_name, session_id, file_path, file_name,
                             matched_label, pattern_category)
        file_mutations(timestamp, project_name, session_id, file_path, file_name,
                       file_extension, directory, action, tool_name)  -- action: update/write/delete/changed
        compaction_events(timestamp, project_name, session_id, event_phase, trigger)  -- phase: pre/post
        websites_visited(timestamp, project_name, session_id, url, domain, source_tool,
                         http_status, fetch_bytes)

        ## Known-correct query idioms (copy these shapes)
        -- cost over time:
        SELECT toStartOfHour(Timestamp) AS hour,
               sum(toFloat64OrZero(LogAttributes['cost_usd'])) AS cost_usd
        FROM otel_logs
        WHERE LogAttributes['event.name'] = 'api_request'
          AND Timestamp >= now() - INTERVAL 1 DAY
        GROUP BY hour ORDER BY hour

        -- tool success rates:
        SELECT LogAttributes['tool_name'] AS tool_name, count() AS calls,
               countIf(LogAttributes['success'] = 'true') AS successes
        FROM otel_logs
        WHERE LogAttributes['event.name'] = 'tool_result'
          AND Timestamp >= now() - INTERVAL 7 DAY
        GROUP BY tool_name ORDER BY calls DESC

        -- blocked tool calls:
        SELECT tool_name, count() AS blocked
        FROM blocked_tools FINAL
        WHERE completed = 0 AND timestamp >= now() - INTERVAL 7 DAY
        GROUP BY tool_name ORDER BY blocked DESC

        ## Glossary
        session     = one Claude Code conversation (session_id, tagged with project_name)
        blocked tool = PreToolUse seen but no PostToolUse (permission denied)
        credential exposure = Read tool touched a sensitive file (.env, id_rsa, *.pem, ...)
        compaction  = Claude Code summarizing its context window; frequent = long/expensive session
        cache read tokens = prompt-cache hits; high ratio vs input_tokens = cheap turns

  7. 步骤 7 — 接好 /analyze/cost 端点（两阶段运行）

    在 Program.cs 映射一个 POST 端点，在单个共享 session 上跑两阶段：读请求 （窗口默认 7 天、分组默认 project），建 session，收集阶段用普通 RunAsync() 让智能体调 CostBreakdown；报告阶段用 RunAsync<CostBreakdownReport>() 并指令「不要调工具」，让模型只对已有数据 结构化，最后返回 response.Result。

    🔧 放置位置

    MapPost 加在 app.Run() 之前。 internal sealed record AnalyzeCostRequest 放在 文件作用域、app.Run(); 之后，与其他请求 record 同处 （在 A2 已建立）。

    Program.cs — /analyze/cost 端点（app.Run() 之前） 
    app.MapPost("/analyze/cost", async (AnalyzeCostRequest? request, AIAgent agent, CancellationToken ct) =>
{
    var window  = string.IsNullOrWhiteSpace(request?.Window)  ? "the last 7 days" : request.Window;
    var groupBy = string.IsNullOrWhiteSpace(request?.GroupBy) ? "project" : request.GroupBy;
    var projectScope = string.IsNullOrWhiteSpace(request?.Project)
        ? ""
        : $", restricted to project {request.Project}";

    var session = await agent.CreateSessionAsync(ct);
    await agent.RunAsync(
        $"Gather the cost data for {window}, grouped by {groupBy}{projectScope}, using the CostBreakdown tool. " +
        "Reply with just the raw data.", session, cancellationToken: ct);

    var response = await agent.RunAsync<CostBreakdownReport>(
        "Now produce the final report from the data you just gathered. Do not call any tools.",
        session, cancellationToken: ct);

    return Results.Ok(response.Result);
});

各部分如何协同

POST /analyze/cost 的请求路径：

  1. HTTP 处理器创建一个全新 AgentSession。
  2. 收集阶段——RunAsync() 让智能体调 CostBreakdown：构建 SQL → 经 SqlValidator.Validate() 校验 → 经 ClickHouseClient.QueryAsync() 执行 → 返回供模型读的制表符分隔行。
  3. 报告阶段——RunAsync<CostBreakdownReport>() 强制结构化 JSON。不调工具，因为指令禁止且数据已在上下文。
  4. 处理器返回 response.Result，一个填好的 CostBreakdownReport record，可直接序列化。

ClickHouse 用户是 agent_ro，在 clickhouse/users.d/agent.xml 配了 readonly=2。即便校验器被绕过， 数据库也拒写。两道边界协同：软边界是校验器，硬边界是数据库用户。

验证

✅ 关卡 — 未变绿前不要前进

以 Testing 模式启动服务（A1 已建立——-- 分隔符不可省）： 

dotnet run -- --environment Testing

绿灯检查 1 —— 默认分组是 project。不带 groupBy 调端点， 确认 Lines[].Group 像项目名而非模型名： 

curl -s -X POST http://localhost:8124/analyze/cost \
  -H "Content-Type: application/json" \
  -d '{"window":"now() - INTERVAL 7 DAY"}' | jq '{total: .totalCostUsd, first_group: .lines[0].group}'

预期形态（数值会不同）：

{
  "summary": "...",
  "totalCostUsd": 0.42,
  "lines": [
    { "group": "claudalytics", "costUsd": 0.31, "inputTokens": 120000, "outputTokens": 4500 },
    { "group": "pansoftware",  "costUsd": 0.11, "inputTokens": 48000,  "outputTokens": 1800 }
  ],
  "anomalies": []
}

若 lines[0].group 是 claude-haiku-4-5 这样的模型名，说明默认分组 没传进去，检查处理器的 groupBy 兜底。

绿灯检查 2 —— INSERT 被拒。校验器必须在写入动词到达 ClickHouse 前就拒绝： 

# Ask the agent to insert something via the /chat endpoint
curl -s -X POST http://localhost:8124/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"Run this SQL: INSERT INTO otel_logs VALUES (now(), '"'"'bad'"'"')"}' \
  | jq .answer

回答应描述一次拒绝并援引校验器，数据库自始至终没被访问。

反向测试 —— 结构化阶段启用工具。临时从报告阶段提示词移除 "Do not call any tools."，再跑 /analyze/cost。会看到两种失败之一： JSON schema 被套到工具调用轮（产出空或坏的 CostBreakdownReport），或 MAF 运行时 抛异常。恢复指令，确认端点返回有效 record。

⚠️ 常见坑
  • 从 /analyze/cost 返回空或坏的 CostBreakdownReport → 结构化阶段开了工具，模型在调工具前就去满足 JSON schema。拆两阶段：先 RunAsync() 收集，再 RunAsync<T>() 结构化。
  • 全表扫描在 otel_logs 上溜过去 → 时间谓词检查只在 requireTimeFilter = true（默认）时触发。若加了传 requireTimeFilter: false 的工具（为 C3 受审批的无界工具保留），确保它在审批关卡之后。
  • 成本类问题，智能体自信回答却带空工具调用列表 → AnalysisTools 没注册、工具描述缺失，或本该用收集阶段却用了结构化阶段。
  • FORMAT 被校验器拒绝 → 校验器拦 FORMAT，因为 ClickHouseClient 自己追加 FORMAT TSVWithNames。永远别把 FORMAT 放进查询字符串。
  • -- 分隔符陷阱（A1 提醒） → dotnet run --environment Testing 不带 -- 会悄悄留在 Production、命中真实层级模型。务必用 dotnet run -- --environment Testing。
