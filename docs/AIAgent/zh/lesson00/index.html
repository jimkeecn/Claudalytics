第 00 课 · L0 · 环境准备

基础设施环境准备：项目、依赖包、密钥，以及 Testing 仪式

★ 无需 LLM

你将学到什么

你要构建的是 Claudalytics Copilot，一个回答 LLM 成本和 ClickHouse telemetry 问题的 .NET agent。如果用默认设置跑每一课，每个关卡（gate）都会按全价调用真实 Claude 模型，而且密钥可能被提交进 git。本课建立一条启动命令：把每个模型锁定到便宜的 Haiku 层级，并从一个被 gitignore 的文件加载 API key，让后续每一课都便宜、可重复、安全。

这里建立的脚手架贯穿全部 19 课：带精确包版本的 .csproj、两个文件的 appsettings 拆分（基础配置 + Testing 覆盖）、存放 Anthropic API key 的 appsettings.Local.json gitignore 模式，以及后续每个关卡都依赖的验证步骤。Docker 推迟到毕业项目（CAP）再讲；现在只跑裸的 dotnet run。

📘 讲解

MAF 项目依赖三个必须一起锁定版本的包： Microsoft.Agents.AI、 Microsoft.Agents.AI.Anthropic 和 Microsoft.Agents.AI.Workflows。其中 Anthropic 提供器包处于预览版（preview）轨道，它的后缀 （-preview.YYMMDD.N）每周都会变化 —— 锁定它 可以防止悄无声息的升级破坏 API。OpenTelemetry 相关包则单独锁定。

Testing 环境并不是一个测试项目 —— 它是由 appsettings.Testing.json 加载的一个 ASP.NET 命名环境，在主机启动时通过给宿主传入 --environment Testing 来激活。它在本课程中做两件事：把全部三个模型层级都覆盖为 claude-haiku-4-5 （让每个关卡只花零点几分钱），并把 Microsoft.Agents.AI 日志命名空间的级别提升到 Debug（在 E2 中观察上下文压缩（compaction）时必需）。除了 D3 里那次真实层级（real-tier）检查之外，你在每一课都会用到这个环境。

-- 分隔符是关键所在。 没有它，dotnet 会把 --environment Testing 当作 它自己的标志解析，而不是传给你程序的参数，于是宿主会悄悄 停留在 Production。这个陷阱在 E2 中会再次被点名，因为 它是"一个本来能用的上下文压缩（compaction）提供器却产生不出任何 Debug 日志"最常见的原因。

动手构建

  1. 创建解决方案和 Web 项目

    Copilot 是一个 Web 服务，所以从 ASP.NET minimal-API 项目起步。创建一个面向 .NET 9 的项目，项目名用 AiAgent：后续课程都从 AiAgent.* 命名空间导入类型，所以名字必须一致。 

    dotnet new sln -n Claudalytics
dotnet new web -n AiAgent -f net9.0
dotnet sln add AiAgent/AiAgent.csproj

  2. 在 AiAgent.csproj 中锁定包版本

    后续课程会用到三个 MAF 包：Microsoft.Agents.AI（agent 运行时）、Microsoft.Agents.AI.Anthropic（Claude provider）、Microsoft.Agents.AI.Workflows（workflow 引擎）。三个 OpenTelemetry 包把 trace 送进 ClickHouse。用下面锁定好的版本替换生成的 AiAgent.csproj。

    AiAgent/AiAgent.csproj 
    <Project Sdk="Microsoft.NET.Sdk.Web">

  <PropertyGroup>
    <TargetFramework>net9.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <NoWarn>$(NoWarn);MAAI001;MEAI001</NoWarn>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="Microsoft.Agents.AI" Version="1.9.0" />
    <PackageReference Include="Microsoft.Agents.AI.Anthropic" Version="1.9.0-preview.260603.1" />
    <PackageReference Include="Microsoft.Agents.AI.Workflows" Version="1.9.0" />
    <PackageReference Include="OpenTelemetry.Exporter.OpenTelemetryProtocol" Version="1.15.3" />
    <PackageReference Include="OpenTelemetry.Extensions.Hosting" Version="1.15.3" />
    <PackageReference Include="OpenTelemetry.Instrumentation.AspNetCore" Version="1.15.2" />
  </ItemGroup>

</Project>

    NoWarn 抑制 MAAI001 和 MEAI001 两个预期警告：compaction 和 chat-reducer API 在 MAF 1.9.0 / M.E.AI 10.5 中标记为实验性，会在 E2 用到。Anthropic provider 包是 preview 轨道，后缀每周变化，必须锁定精确版本以防升级破坏 API。然后执行还原： 

    dotnet restore AiAgent/AiAgent.csproj

  3. 编写基础 appsettings.json

    这个文件存放可安全提交的非密钥配置：监听 URL、日志级别、三个模型层级（model tier）。D3 引入的 ModelTiers 辅助类读取层级名（Light、Analyst、Reasoning）。每个创建 agent 的课程都从这份配置读取模型名。

    AiAgent/appsettings.json 
    {
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*",
  "Urls": "http://localhost:8124",
  "CLICKHOUSE_URL": "http://localhost:8123",
  "CLICKHOUSE_USER": "agent_ro",
  "Models": {
    "Light": "claude-haiku-4-5",
    "Analyst": "claude-sonnet-4-6",
    "Reasoning": "claude-opus-4-8"
  }
}

  4. 编写 appsettings.Testing.json

    这个文件是每一课的成本与安全保障网。它把三个层级全部覆盖为 Haiku，并为 MAF 命名空间启用 Debug 级别的日志。它是要提交的 —— 它不含任何密钥，且必须在每台机器上都表现一致、可预测。

    AiAgent/appsettings.Testing.json 
    {
  "Models": {
    "Light": "claude-haiku-4-5",
    "Analyst": "claude-haiku-4-5",
    "Reasoning": "claude-haiku-4-5"
  },
  "Logging": {
    "LogLevel": {
      "Microsoft.Agents.AI": "Debug"
    }
  }
}

    为什么三个层级都用 Haiku？这些层级的存在，是为了在生产环境中让路由器（router）回合使用 Light 模型，而深度分析回合使用 Reasoning 模型。而在 Testing 里，你希望所有回合都同样便宜 —— 也同样可观测（observability）—— 同时不改动任何调用点。这种覆盖是彻底的：任何读取 config["Models:Reasoning"] 的课程代码在 Testing 下拿到的都是 Haiku。

  5. 创建被 gitignore 的密钥文件

    先把 appsettings.Local.json 加入 .gitignore，然后再创建该文件。绝不要颠倒这个顺序 —— 密钥文件哪怕一瞬间也不能出现在 git 里。 

    # In the repo root .gitignore — add this line:
**/appsettings.Local.json

    然后创建该文件（不要提交它）：

    AiAgent/appsettings.Local.json ← gitignored 
    {
  "ANTHROPIC_API_KEY": "sk-ant-…your-key-here…"
}

    Anthropic provider 包在启动时从配置读取 ANTHROPIC_API_KEY。在 Program.cs 中最后加载这个文件（在所有其他配置源之后），让它的 key 盖过同名环境变量。文件里只放密钥：ANTHROPIC_API_KEY 和可选的 CLICKHOUSE_PASSWORD。

    AiAgent/Program.cs（节选 —— 完整文件见第 6 步） 
    var builder = WebApplication.CreateBuilder(args);

builder.Configuration.AddJsonFile(
    "appsettings.Local.json", optional: true, reloadOnChange: true);

    文件设为 optional: true，所以缺文件时 CI 不会失败。CI 机器上没有本地文件，改由 CI 把 key 作为环境变量注入。

  6. 添加健康检查端点（endpoint）并启动应用

    添加一个最小的健康检查端点，这样在任何智能体（agent）出现之前你就有东西可以 curl 了。下面就是本课 Program.cs 的全部内容。

    AiAgent/Program.cs 
    var builder = WebApplication.CreateBuilder(args);

builder.Configuration.AddJsonFile(
    "appsettings.Local.json", optional: true, reloadOnChange: true);

var app = builder.Build();

app.MapGet("/healthz", () => Results.Ok(new { status = "ok" }));

app.Run();

    现在带上 Testing 环境标志启动：

    cd AiAgent
dotnet run -- --environment Testing

    -- 不是可选的。它告诉 dotnet：它之后的所有内容都是传给你程序的参数，而不是传给 dotnet run 命令本身的。没有它， --environment 会被 dotnet 解析，而不是被 ASP.NET 的宿主构建器解析，于是你的进程会悄悄启动到 Production 环境。

环境配置栈是如何加载的

ASP.NET 按以下顺序加载配置源，越靠后的源会盖过越靠前的源：

  1. appsettings.json —— 基础值（已提交）
  2. appsettings.{Environment}.json —— 环境覆盖层；在 Testing 下即 appsettings.Testing.json（已提交）
  3. 环境变量 —— CI 在这里注入密钥
  4. appsettings.Local.json —— 开发者密钥，最后加载（被 gitignore）

结果是：在你的机器上，Anthropic API key 来自 appsettings.Local.json；在 CI 中它来自环境变量；两种情况下这个 key 都会盖过此前的任何配置源。只要环境是 Testing，模型层级就会被 appsettings.Testing.json 覆盖为 Haiku。

验证

✅ 关卡（gate）— 未变绿前不要前进

绿灯检查 1 —— 在控制台输出中确认环境。

当你运行 dotnet run -- --environment Testing 时，ASP.NET 宿主会在启动期间把它的环境写入控制台。请找这一行： 

info: Microsoft.Hosting.Lifetime[0]
      Hosting environment: Testing

如果你看到的是 Production，那就是你忘了 -- 分隔符。

绿灯检查 2 —— 健康检查端点有响应。

curl http://localhost:8124/healthz
# Expected: {"status":"ok"}

反向测试 —— 悄无声息的 Production 陷阱。

不带分隔符运行，观察其中的差异：

# Wrong — dotnet consumes --environment Testing itself
dotnet run --environment Testing

# The console will print:
#   Hosting environment: Production
# appsettings.Testing.json is NOT loaded.
# All model tiers stay at the production values (Sonnet, Opus).
# Any gate that checks for Haiku spans will fail.

这是整门课程中最重要的反向测试。每一课的"验证"部分都假定你处于 Testing。如果不是，那 Haiku 锁定带来的成本保证就没了，而上下文压缩（compaction）（E2）的 Debug 日志也会被抑制。

ℹ️ 说明

Docker 被推迟了。整个课程中你都直接用 dotnet run 运行后端。在毕业项目（CAP）之前你不会需要 Docker。在那之前，直接运行 dotnet run -- --environment Testing 即可；appsettings.json 里的 ClickHouse URL 指向 localhost，是为你之后拥有本地实例时准备的，但环境准备这几课并不需要它。

⚠️ 常见坑
  • 控制台显示 Hosting environment: Production → 你运行的是 dotnet run --environment Testing，少了 -- 分隔符。Dotnet 把这个标志吃掉了，你的程序从来没看到它。永远要写： dotnet run -- --environment Testing。
  • 构建报错 MAAI001 或 MEAI001 → .csproj 中缺少 NoWarn 那一行。这些是实验性上下文压缩（compaction） API 的预期警告；现在就抑制它们，免得在 E2 中污染课程输出。
  • 还原失败或找不到 preview 包 → Microsoft.Agents.AI.Anthropic 的版本后缀是带时间戳的（1.9.0-preview.260603.1）。如果 NuGet 无法解析它，请到 NuGet 列表页 查找最新的 1.9.0-preview.* 并更新版本字符串。锁定到你解析出来的那个版本；不要使用 * 通配符。
  • 运行时找不到 API key → 确认 appsettings.Local.json 存在于项目目录中（与 AiAgent.csproj 同级），而不是解决方案根目录。 AddJsonFile 是相对于内容根（content root）解析的，而用 dotnet run 运行时内容根就是项目目录。
  • appsettings.Local.json 出现在 git status 里 → 是在文件已经被跟踪之后才添加 .gitignore 条目的。运行 git rm --cached AiAgent/appsettings.Local.json 在不删除文件的情况下取消跟踪，然后提交 .gitignore 的改动。
