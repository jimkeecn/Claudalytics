## Details

### 🟢 `num_hooks` / `num_success` value semantics (non-interactive sessions)
Changelog: *"Changed OpenTelemetry hook events in non-interactive sessions to leave two built-in hooks out of `num_hooks` and `num_success` after Bash and PowerShell calls."*

- These fields are consumed only in the **Event Timeline** panel of `docker-stack/grafana/dashboards/otel-overview.json`, in the `hook_execution_start` / `hook_execution_complete` detail strings:
  - `concat(LogAttributes['hook_event'], ' (', LogAttributes['num_hooks'], ' hooks)')`
  - `concat(..., LogAttributes['num_success'], ' ok')`
- No materialized view reads them (the MVs — `003` credential, `005` file_mutations, `007` blocked_tools, `011` websites_visited — don't touch hook counts).
- **Effect:** in headless / `claude -p` / SDK sessions the displayed "N hooks / N ok" after a Bash or PowerShell call shrinks by up to 2. Cosmetic only; interactive sessions unaffected. **No action required.**

### 🟢 `vcs.*` resource attributes now reliably emitted (optional adoption)
Changelog: *"Fixed OpenTelemetry repository attributes (`vcs.*`) missing from Claude Desktop sessions that start on a pre-started process."*

- Grep confirms the repo **does not reference `vcs.*` anywhere** today; it derives project context solely from `ResourceAttributes['project.name']` (set via `OTEL_RESOURCE_ATTRIBUTES` per `plugin/skills/init-claudalytics/SKILL.md`).
- Because these attributes are now dependable, the stack could optionally surface repository/branch dimensions (e.g. `ResourceAttributes['vcs.repository.url']`, `vcs.ref`) in dashboard variables or the Per-User leaderboard without any ingestion change — the ClickHouse `ResourceAttributes` map already stores whatever arrives.
- **Effect:** purely additive opportunity; nothing breaks if ignored.
