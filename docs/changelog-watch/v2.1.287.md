## Details

### 🟠 Mid — `prompt_text` duplicates raw prompt content in `otel_logs`

**Changelog text:** "Added `prompt_text` to the OpenTelemetry `user_prompt` event, a copy of `prompt` for backends that nest dotted keys; drop or mask it wherever you drop or mask `prompt` (anthropics/claude-code#70763)."

**Why it matters here:**
- The init skill sets `OTEL_LOG_USER_PROMPTS = 1` (`plugin/skills/init-claudalytics/SKILL.md:115`), so Claude Code's **native** `user_prompt` OTel event is emitted with the full prompt string in the `prompt` attribute.
- The repo consumes that event today: `otel-overview.json` panel ~L1270 reads `any(LogAttributes['prompt'])` as `prompt_text` (its own alias) for the "top prompts by cost" panel, and panels at L1165/L1456/L1575 key off `event.name='user_prompt'` / `prompt.id` / `prompt_length`.
- `otel_logs.LogAttributes` is a flat `Map(LowCardinality(String), String)` auto-created by the OTel Collector's ClickHouse exporter (`create_schema: true`). The new `prompt_text` key will therefore **auto-ingest with no schema change** — and the existing `LogAttributes['prompt']` key is **unchanged**, so no query or panel breaks.

**The Mid concern is governance, not breakage:**
- With prompts already logged in cleartext, every `user_prompt` row now carries the full prompt **twice** (`prompt` and `prompt_text`) for the 2160h (`ttl: 2160h`) retention window — roughly doubling the per-prompt storage and the sensitive-data footprint.
- The repo does **no** masking/redaction of `prompt` today (grep for mask/redact/sanitize = none), so there is nothing to keep in sync *yet*. The action item is to decide policy before the duplicate silently grows the PII surface.

**Note on the "nested dotted keys" rationale:** `prompt_text` exists for backends that nest `prompt.id` under a `prompt` object (colliding with the `prompt` string). ClickHouse's flat Map does **not** have that collision, so Claudalytics gains no functional benefit from adopting `prompt_text` — it is pure duplication here.

### 🟢 Low — 1M context default drops `[1m]` suffix on model ids

`field-mapping.ts` captures `attrs["model"]` on SessionStart verbatim and the dashboard renders `model` strings as-is (e.g. `SessionStart` detail `source · model`, api_request detail). Nothing splits or matches on a `[1m]` suffix, so the change is cosmetic for this repo. Flagged only so future model-based filters/dashboards expect suffix-less Opus/Fable ids on Bedrock/Vertex/Foundry/apps-gateway deployments.

## Recommended actions

- [ ] **Decide prompt-content policy** now that `user_prompt` carries both `prompt` and `prompt_text`. Options: (a) accept the duplication (no action), (b) drop `prompt_text` at the collector to avoid doubling PII/storage, or (c) if prompt logging is undesired, set `OTEL_LOG_USER_PROMPTS=0` in `plugin/skills/init-claudalytics/SKILL.md`.
- [ ] If option (b): add a `transform`/`attributes` processor to `docker-stack/otel-collector-config.yaml` to delete `prompt_text` from log records (e.g. `delete_key(attributes, "prompt_text")`), and wire it into the `logs` pipeline.
- [ ] If any prompt masking/redaction is ever added, **mask `prompt_text` alongside `prompt`** (per the changelog directive) — document this coupling wherever the masking lives.
- [ ] **No ingestion/MV/dashboard changes required** — `LogAttributes['prompt']` and all `user_prompt` panels keep working unchanged.
- [ ] **No hooks-server / ClickHouse MV changes** — no new hook events or tool renames in this release.
- [ ] (Awareness only) Expect suffix-less `[1m]` model ids in the `model` attribute on 1M-context deployments; revisit if a future dashboard filters on model id.
