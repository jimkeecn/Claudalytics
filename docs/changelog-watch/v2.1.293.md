### Details

#### 🟠 Mid — New default Haiku model breaks the hardcoded latency panel filter

`docker-stack/grafana/dashboards/otel-overview.json` (around line 913) contains an API-request latency panel whose query hardcodes two model ids:

```sql
quantileIf(0.50)(toUInt32OrZero(LogAttributes['duration_ms']), LogAttributes['model']='claude-opus-4-6')   AS "opus p50",
...
quantileIf(0.50)(toUInt32OrZero(LogAttributes['duration_ms']), LogAttributes['model']='claude-haiku-4-5-20251001') AS "haiku p50",
...
```

2.1.293 makes `claude-haiku-5-5` the default Haiku model on the Anthropic API. Any session using the new default now emits `LogAttributes['model'] = 'claude-haiku-5-5'`, which does **not** match `claude-haiku-4-5-20251001`. Result: the panel's three `haiku` series silently flatline to empty while real Haiku latency data continues to land in `otel_logs`.

Scope notes:
- **No ingestion/MV impact.** `field-mapping.ts` maps the `model` field dynamically (`attrs["model"] = safeString(prop(data, "model"))`), and no materialized view keys off a specific model id, so rows are stored correctly.
- The `opus` series on the same panel hardcodes `claude-opus-4-6` (also stale, but a pre-existing condition not introduced by this changelog) — worth fixing in the same pass.
- This is the **only** place in the repo that hardcodes model ids; dashboard model dropdowns and per-model aggregates elsewhere derive the model dynamically.

### Recommended actions

- [ ] Update the latency panel in `docker-stack/grafana/dashboards/otel-overview.json` (~line 913) to filter Haiku on `claude-haiku-5-5` (or make the panel model-agnostic, e.g. group by `LogAttributes['model']` / drive it from the existing model template variable instead of hardcoding ids).
- [ ] While there, refresh the hardcoded `opus` filter (`claude-opus-4-6`) to the current Opus id, or switch both series to a dynamic model variable so future model releases don't silently empty the panel.
- [ ] Consider a follow-up to generally eliminate hardcoded model ids from dashboard SQL to make the pipeline resilient to model renames.
- [ ] No action needed for the `at_mention` cap, `agentType`, or `isDeferred` changes — the repo does not depend on them.
