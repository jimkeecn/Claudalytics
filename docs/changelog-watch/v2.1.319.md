# [CC Changelog] v2.1.319 — no impact

**v2.1.319 — no impact** on Claudalytics ingestion, materialized views, or dashboards.

- Source: https://code.claude.com/docs/en/changelog (version 2.1.319, 2026-11-06)
- Scan date: 2026-11-06

## Why no impact

The 2.1.319 release is dominated by changes to the Claude apps gateway, auto mode,
permission settings, VSCode, cloud sessions, Claude in Chrome, the self-hosted runner,
and Claude Tag. None of the repo's hardcoded Claude Code surfaces are renamed, removed,
or schema-changed:

- **Hook events** (`hook-events.ts`, `field-mapping.ts` `EVENTS_TO_EMIT`): no event in the
  26-name set was renamed or removed, and 2.1.319 introduces no new hook event name.
- **Tool-name mappings** (`field-mapping.ts`): `Read` / `Edit` / `Write` / `Bash` /
  `WebFetch` / `WebSearch` / `Agent` and their emitted attribute keys are unchanged.
- **OTel metrics ingested** (dashboard `otel-overview.json`): the repo queries only
  `claude_code.active_time.total`, `claude_code.commit.count`, and
  `claude_code.lines_of_code.count` — all unchanged. The single OTel-metrics item in
  2.1.319 fixes `claude_code.session.count` (Agent SDK `prewarm()` over-counting), a
  metric this repo does **not** ingest or dashboard, so it has no effect here.
- **Materialized views** (`003`/`005`/`007`/`011`): hardcoded tool names, `hooks.*`
  event names, and attribute keys are all unaffected.
- **Init skill** (`init-claudalytics/SKILL.md`): the OTel env-var names it sets and the
  health-check response schema are unchanged. The new env vars in 2.1.319
  (`CLAUDE_CODE_DISABLE_FEATURE_FLAGS`, `CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND`,
  `CLAUDE_CODE_DISABLE_MCP_TASKS`) are optional opt-outs, not required for ingestion.

MCP-task backgrounding and the `permissions.denyInsteadOfPrompting` setting change
runtime behaviour but flow through the existing generic `PreToolUse` / `PostToolUse` /
`PermissionDenied` hook paths, which the repo already captures — no new fields needed.
