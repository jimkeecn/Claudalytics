### Details

#### 🟢 MCP tool / WebFetch / WebSearch outputs on OTel span events (`OTEL_LOG_TOOL_CONTENT=1`)

**What changed upstream:** Claude Code now attaches MCP tool, `WebFetch`, and `WebSearch` outputs to OpenTelemetry span events, gated by `OTEL_LOG_TOOL_CONTENT=1`.

**Repo state today:**
- `plugin/skills/init-claudalytics/SKILL.md` already exports `OTEL_LOG_TOOL_CONTENT=1` (line ~118) and `OTEL_TRACES_EXPORTER=otlp`.
- `docker-stack/otel-collector-config.yaml` already runs a `traces` pipeline exporting to the ClickHouse `otel_traces` table, so these enriched span events will begin landing there automatically once users are on 2.1.283 — no config change required to receive them.
- The analytics MVs (`011_websites_visited_mv.sql`, etc.) read exclusively from `otel_logs` (the hooks path), where `field-mapping.ts` already extracts `search_urls`, `http_status`, and `fetch_bytes`. So **existing dashboards keep working unchanged** — nothing depends on the new span-event fields.

**Why it's only Low / an improvement, not a break:** No existing attribute key or table is renamed. The new data is additive and arrives on a channel (`otel_traces`) that no current MV consumes. The one genuine gap it could close is **MCP tool output** — `field-mapping.ts` only maps `mcp_server_name` for `Elicitation`/`ElicitationResult` and treats `mcp__*` tool calls generically via `PostToolUse`, with no per-tool output extraction. If richer MCP observability is desired, the native span events are now the lowest-effort source.
