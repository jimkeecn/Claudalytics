## Details

_No High or Mid severity findings in this release._ The single actionable item is a Low-severity improvement:

### 🟢 Low (Improvement) — native `tool.output` span event now carries MCP tool / WebFetch / WebSearch outputs

Claude Code now attaches MCP tool, WebFetch, and WebSearch outputs to its **native** `tool.output` OpenTelemetry span event, gated on `OTEL_LOG_TOOL_CONTENT=1`.

- **Not a break.** The hooks-server ingestion path (`hooks.PreToolUse` / `hooks.PostToolUse` → `otel_logs`) and the URL/website analytics in `011_websites_visited_mv.sql` are unaffected — they read `LogAttributes` written by `field-mapping.ts`, not native span events. No attribute or event name was renamed or removed.
- **What changes in practice.** `plugin/skills/init-claudalytics/SKILL.md` (Step 5) already writes `OTEL_LOG_TOOL_CONTENT = 1`, and the collector forwards traces to the `otel_traces` table (`otel-collector-config.yaml`). So these richer `tool.output` payloads will start landing in `otel_traces` automatically. Watch for a modest increase in trace-table volume; the collector `ttl: 2160h` (90d) still applies.
- **Adoption opportunity.** MCP tool calls currently flow through the hooks pipeline only generically (`tool_name` + `tool_input`, no MCP-specific output capture in `field-mapping.ts`). The native `tool.output` span event is a candidate source if the repo ever wants MCP tool *output* analytics or a WebFetch/WebSearch content view sourced from traces rather than hooks. Optional — no action required to keep current ingestion correct.
