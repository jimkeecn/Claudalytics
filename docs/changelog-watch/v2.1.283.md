## Details

### 🟢 Improvement — `tool.output` span event enriched (Low)

**Change:** "Added MCP tool, WebFetch and WebSearch outputs to the `tool.output` OpenTelemetry span event when `OTEL_LOG_TOOL_CONTENT=1`."

**Where it lands in this repo:**
- `plugin/skills/init-claudalytics/SKILL.md` already writes `OTEL_LOG_TOOL_CONTENT = 1` (line 118) and `OTEL_TRACES_EXPORTER = otlp` (line 117) into `.claude/settings.local.json`, so the enriched span event will begin appearing in the native-trace stream.
- `docker-stack/otel-collector-config.yaml` routes the `traces` pipeline into the `otel_traces` table (`traces_table_name: otel_traces`, line 24).

**Why it does not break anything:** The repo's web/URL analytics (`011_websites_visited_mv.sql`) and all other MVs read from `otel_logs`, which is fed by the **hooks** path (`hooks-server` → OTel logs), not by native traces. WebFetch/WebSearch URLs are already captured from `PostToolUse` hook attributes (`search_urls`, `http_status`, `fetch_bytes`, `bash_urls`) in `field-mapping.ts`. The span-event enrichment is additive to `otel_traces` only.

**Optional upside:** If richer per-tool output (including MCP tool results, which the hooks path does not currently decode) becomes worth surfacing, it is now present in `otel_traces` and could feed a future MV or dashboard panel. No action required for correctness.

### 🟢 Info — stricter plugin validation is a no-op for this repo (Low)

**Changes:**
- "Fixed `claude plugin validate` saying Claude Code accepts a plugin or marketplace name it cannot install; such names in `marketplace.json` now fail validation."
- "Fixed `claude plugin validate` passing plugins whose `outputStyles`, `themes`, `monitors`, or `lspServers` paths are missing or point outside the plugin directory."
- "Fixed `claude plugin details` showing 0 MCP servers for plugins that declare their servers in `plugin.json`."

**Assessment:** The repo's `plugin/.claude-plugin/plugin.json` (name `claudalytics`, no `outputStyles`/`themes`/`monitors`/`lspServers`, no `mcpServers`) and `.claude-plugin/marketplace.json` (plugin name `claudalytics`, `source: ./plugin`) already satisfy the tightened rules. No manifest change is needed; a single `claude plugin validate` run is enough to confirm continued compliance.
