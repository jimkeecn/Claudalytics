### Details

#### 🔴 High — OTel env vars in local settings are ignored (breaks ingestion)

Changelog text:

> Changed project and local settings to ignore OpenTelemetry variables that turn on export, set its endpoint, or capture content, like `CLAUDE_CODE_ENABLE_TELEMETRY` and `OTEL_LOG_*`

`plugin/skills/init-claudalytics/SKILL.md` **Step 5 — Write Configuration** writes all of the following into `.claude/settings.local.json`:

```
CLAUDE_CODE_ENABLE_TELEMETRY        = 1     # turns on export  -> IGNORED
OTEL_EXPORTER_OTLP_ENDPOINT         = http://localhost:4317   # sets endpoint -> IGNORED
OTEL_LOG_TOOL_DETAILS               = 1     # OTEL_LOG_*  (capture content) -> IGNORED
OTEL_LOG_USER_PROMPTS               = 1     # OTEL_LOG_*  (capture content) -> IGNORED
OTEL_LOG_TOOL_CONTENT               = 1     # OTEL_LOG_*  (capture content) -> IGNORED
OTEL_METRICS_EXPORTER / OTEL_LOGS_EXPORTER / OTEL_TRACES_EXPORTER / ...
OTEL_RESOURCE_ATTRIBUTES            = project.name=<PROJECT_NAME>
```

`.claude/settings.local.json` is a **local settings file** — exactly the source the change now filters. With `CLAUDE_CODE_ENABLE_TELEMETRY` and the endpoint dropped, Claude Code exports **nothing**: the OTel Collector (`docker-stack/otel-collector-config.yaml`) receives no data, and every downstream table/materialized view (`docker-stack/clickhouse/init/*.sql`) and Grafana dashboard (`docker-stack/grafana/dashboards/otel-overview.json`) goes empty for freshly-initialized projects. Existing projects that relied on these local-settings vars break on their next Claude Code upgrade.

Note: the changelog scopes this to **project and local** settings. **User settings** (`~/.claude/settings.json`), **managed settings**, `--settings`, and the shell environment are still honored — that is the basis for the fix below. (The plugin's `forward-hook.sh` reads `project_name` from `.claude/analytics.json`, not env, so the hooks-server ingestion path itself is unaffected; the break is only the OTel metrics/traces/logs path via env config.)

#### 🟠 Mid — health check cannot see the "ignored" state

`SKILL.md` Step 4 classifies OTel config purely by reading key/value pairs in `settings.local.json` (Case A `skip_otel` / Case B conflict / Case C `replace`). It will now happily report a project as configured while Claude Code discards those very keys. `session-start-health-check.sh` likewise has no signal that telemetry is actually off. The new `claude doctor` / `/status` "ignored telemetry variables" report is the supported detection surface the skill/health-check should adopt.

### Recommended actions

- [ ] **Fix onboarding target (High):** Update `plugin/skills/init-claudalytics/SKILL.md` Step 5 to write the OTel env vars to a source Claude Code still honors — user settings (`~/.claude/settings.json`) or the shell environment — instead of `.claude/settings.local.json`. Keep `project.name` per-project via `OTEL_RESOURCE_ATTRIBUTES` in a still-honored source, or continue relying on `analytics.json` for project attribution.
- [ ] **Update detection (High/Mid):** Revise Step 2 and Step 4 so OTel-key detection reads the new location, and treat keys found only in local/project settings as "present but ignored" (prompt the user to migrate them).
- [ ] **Harden health check (Mid):** Have `session-start-health-check.sh` / the report step surface Claude Code's own ignored-telemetry notice (e.g. parse `claude doctor` / `/status`) so a broken telemetry config is caught at session start rather than showing empty dashboards.
- [ ] **Docs (Low):** Note in the plugin README / SKILL that OTel env vars must live in user settings or the environment on Claude Code ≥ 2.1.282; `.claude/settings.local.json` no longer enables telemetry.
- [ ] **Version bump (on fix):** When the above touches the plugin folder, bump the version in `plugin/.claude-plugin/plugin.json`, `marketplace.json`, and the `session-start-health-check.sh` version referenced in `SKILL.md`, per repo CLAUDE.md.
- [ ] **Regression check:** After migrating config, run `/validate-infra` and confirm the OTel Collector receives metrics/logs and the `otel-overview` dashboard repopulates.
