## Details

### 🟢 Agent tool `effort` parameter (Improvement)

The changelog adds an `effort` parameter to the Agent tool so Claude can run a sub-agent at a requested effort level.

The repo already models the Agent tool's dispatch inputs in `hook-events.ts`:

```ts
export interface AgentInput {
  prompt: string;
  description?: string;
  subagent_type: string;
  model?: string;
}
```

…and the subagent dashboard (`otel-overview.json`) explicitly surfaces `model` and `subagent_type` from Agent-tool dispatch. `effort` is the same kind of dispatch dimension and is a natural thing to track (e.g. correlating effort level with subagent token spend via the existing `agent.total_tokens` / `agent.input_tokens` attributes already emitted in the `PostToolUse` Agent branch).

**No breakage:** the `PreToolUse` / `PostToolUse` handlers stringify the entire `tool_input` into the `tool_input` attribute, so an `effort` field flows through today without changes. This is purely an optional enhancement to make the value first-class (queryable column) rather than JSON-buried.

**Suggested (optional) adoption:**
1. Add `effort?: string;` to `AgentInput` in `hook-events.ts` for type completeness.
2. In `field-mapping.ts`, inside the `Agent` handling, emit an `agent.effort` attribute from `tool_input.effort` (mirror how `model` is already a tracked dispatch dimension).
3. Optionally add an `effort` breakdown to the subagent dispatch panel in `otel-overview.json`.

> ⚠️ If adopted, these touch the hooks-server source — per the repo's `CLAUDE.md` "Update Plugin Version Number" rule, check whether a plugin version bump is also required (`plugin.json`, `marketplace.json`, and the `session-start-health-check.sh` version in `SKILL.md`). This audit-trail report itself changes no plugin code and needs no bump.
