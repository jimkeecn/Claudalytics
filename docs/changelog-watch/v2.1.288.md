## Details

### 🟠 Mid — `tool_decision` / `blocked_on_user` `source`+`decision` corrected in headless/SDK/hook-approval sessions

Two related upstream fixes in 2.1.288:

1. *"Fixed OpenTelemetry `claude_code.tool.blocked_on_user` spans reporting `unknown` source or decision in `-p` and SDK sessions and for PreToolUse hook approvals"*
2. *"Fixed permission asks that ended unanswered, in `-p` or on an interrupted turn, emitting no `tool_decision` event"*

The repo ingests Claude Code's **native** OTel telemetry (configured by `plugin/skills/init-claudalytics/SKILL.md` Step 4: `CLAUDE_CODE_ENABLE_TELEMETRY=1`, `OTEL_LOGS_EXPORTER=otlp`, etc.) directly into `claudalytics.otel_logs`. The dashboard panel **Tool Decisions: Accept vs Reject (per tool, per source) [KAN-21]** depends on exactly the attributes these fixes touch:

```sql
SELECT LogAttributes['tool_name'] AS tool,
       concat(LogAttributes['source'], ':', LogAttributes['decision']) AS src_decision,
       count() AS n
FROM claudalytics.otel_logs
WHERE LogAttributes['event.name'] = 'tool_decision'
GROUP BY tool, src_decision
ORDER BY n DESC
```

**Before the upgrade:** for headless (`-p`), SDK, and PreToolUse-hook-approved decisions, `source`/`decision` were `unknown` (so rows collapsed into `unknown:unknown`), and some unanswered/interrupted asks emitted no event at all (missing rows entirely).

**After the upgrade:** those rows carry correct `source`/`decision`, and previously-missing asks are now counted.

**Impact:** positive and automatic — the hardcoded panel starts showing accurate, more complete data. No attribute was renamed or removed, so nothing breaks. The only caveat: historical rows logged by older Claude Code versions keep their `unknown:unknown` bucket, so a mixed time range may show both the legacy `unknown` bucket and the new correct values side by side.
