## Why no impact

The notable items in 2.1.284 were checked against the repo and none touch ingestion, materialized views, or dashboards:

- **New model `claude-sonnet-5-5`** — The repo never hardcodes a model whitelist. `field-mapping.ts` maps `model` as a free-form string, the dashboard's Model Usage panel uses `GROUP BY LogAttributes['model']` dynamically, and cost comes from Claude Code's own emitted `cost_usd` attribute (not a model-keyed pricing table). The new model flows through and appears in dashboards automatically.
- **Gateway telemetry changes** (`telemetry.forward_to` with `auth: { google: {} }`, `private_key_jwt` IdP auth) — These concern the **Claude apps gateway's** own telemetry forwarding to Google Cloud OTLP. Claudalytics runs its own otel-collector + hooks-server pipeline and does not depend on the gateway forwarder, so there is no impact on `otel-collector-config.yaml` or `otel-emitter.ts`.
- **Status line `rate_limits.spend_limit` gains `used_usd`, `limit_usd`, `period`** — This is status-line JSON schema, not a hook event. The hooks-server ingests hook events only (`hook-events.ts`), so there is nothing to adopt or break.
- **No new hook events or tool names** — This release introduces no new `hook_event_name` values and no new tool names, so `hook-events.ts`, `field-mapping.ts` (EVENTS_TO_EMIT / tool-name mapping), the ClickHouse MVs (003/005/007/011), `plugin/hooks/hooks.json`, and `init-claudalytics/SKILL.md` are all unaffected. The `StopFailure` error enum is unchanged.
- **Everything else** (keybindings, `/mcp reconnect all`, VSCode fixes, Claude Tag, vim mode, MCP/plan-usage fixes, Elicitation hook decision fix) — no bearing on the telemetry ingestion pipeline.
