## Verdict

`v2.1.304 — no impact`

No change in this release touches the Claude Code internals that Claudalytics
hardcodes: hook event names/fields, the forwarded-hook set, OTel attribute
keys, materialized-view tool/attribute names, OTel env-var names, or the
health-check response schema.

## Notes (why no impact)

- The 26 forwarded hook events in `plugin/hooks/hooks.json` and the interfaces
  in `docker-stack/hooks-server/src/hook-events.ts` are unchanged — nothing in
  this release renames, removes, or adds a hook event name or field in the
  forwarded-hook stream.
- `e.isReadOnly` and `decider: "person"` were added to a mod's **`tool.check`**
  event. That is a mod-SDK permission callback, not part of the forwarded hook
  event stream (`forward-hook.sh` / `hooks.json`), so the hooks-server,
  materialized views, and dashboards do not ingest it. Not adoptable through
  this pipeline.
- The OpenTelemetry-related items are Claude Code bug fixes that *help*
  ingestion and change no schema the repo depends on:
  - "Fixed OpenTelemetry settings delivered through server-managed settings
    being ignored for the whole session…" — no OTel attribute/env-var name
    change.
  - "Fixed Remote Control failing to start … when DISABLE_TELEMETRY or
    DO_NOT_TRACK is set…" — no repo surface affected.
- "[VSCode] Fixed … SessionStart command hook … time no longer counts toward
  the limit" is favorable for the repo's `session-start-health-check.sh`
  SessionStart hook; no change required.
- No changes to `docker-stack/hooks-server/src/field-mapping.ts`
  (EVENTS_TO_EMIT / attribute mapping), `docker-stack/clickhouse/init/*.sql`
  materialized views, `docker-stack/otel-collector-config.yaml`,
  `docker-stack/hooks-server/src/otel-emitter.ts`, or
  `plugin/skills/init-claudalytics/SKILL.md` are warranted.
