## Details

### 🟢 Improvement (Low) — `tool_decision` native OTel event gains reliable attributes

**Changelog text:** *"Fixed `classifier_category` missing from most OpenTelemetry `tool_decision` events, and new attributes pushing out `tool_use_id`, `tool_source`, and `tool_parameters` when `OTEL_LOGRECORD_ATTRIBUTE_COUNT_LIMIT` is low."*

`tool_decision` is a **native Claude Code OTel log event** (emitted directly to the collector, not via the hooks-server), so it lands in `claudalytics.otel_logs` and is read by Grafana. Two panels consume it:

- `otel-overview.json:805` — tool-decision breakdown: `concat(LogAttributes['source'], ':', LogAttributes['decision'])`
- `otel-overview.json:1456` — session activity feed: `concat(LogAttributes['decision'], ' (', LogAttributes['source'], ')')`

Both read only `source` and `decision`. This release does **not** rename or remove either, so there is **no break**. What changes is that four other attributes now arrive dependably on these events:

- `classifier_category` — the auto-mode classifier's category for the decision. Not currently surfaced anywhere in the repo; a candidate new dimension for a "why was this tool auto-allowed/denied" view.
- `tool_use_id` — lets `tool_decision` rows be joined to the matching `hooks.PreToolUse` / `tool_result` invocation (the hooks-server already stores `use_id` from `tool_use_id`, see `field-mapping.ts:126/145/220/243`).
- `tool_source`, `tool_parameters` — richer provenance for the decided tool.

**Watch item (not a break today):** the changelog names `tool_source` as a *separate* attribute from `source`. As of 2.1.302 both coexist and the dashboard's `source` reference is correct. If a future release deprecates `source` in favour of `tool_source`, the two panels above would silently lose the `(…)` qualifier — worth re-checking on the next changelog that touches `tool_decision`.

No action is required for correctness; this is purely an opportunity to enrich the dashboard with newly-reliable data.
