### Details

#### Improvement — cache-write lifetime split on `api_request`

Claude Code now emits two additional token counters on the native `api_request` OTel event:

- `cache_creation_5m_tokens` — cache writes with a 5-minute TTL
- `cache_creation_1h_tokens` — cache writes with a 1-hour TTL

These **supplement** (do not replace) `cache_creation_input_tokens`, which the "Total tokens" panel already sums at `docker-stack/grafana/dashboards/otel-overview.json:2445`:

```
LogAttributes['input_tokens'] + LogAttributes['output_tokens']
  + LogAttributes['cache_read_input_tokens'] + LogAttributes['cache_creation_input_tokens']
```

Because the total field is retained, **no panel breaks and no data is lost today**. The opportunity: 1h cache writes are priced higher than 5m writes, so a breakdown panel (or adding the two new fields to the cost/efficiency panels at ~line 162/177) would make cache-cost attribution more precise. Pure volume math (not manual pricing) runs off these counts; `cost_usd` is still supplied by Claude Code directly, so reported spend stays correct regardless.

⚠️ **Watch item:** if a future release *deprecates* `cache_creation_input_tokens` in favour of the split fields, the Total-tokens panel would silently under-count cache writes. This release does not do that — flagged only so it's on the radar for the next changelog scan.

#### Improvement — GenAI semantic-convention trace attributes

`gen_ai.provider.name`, `gen_ai.conversation.id`, `gen_ai.tool.name`, and `error.type` are now attached to trace spans. The collector's traces pipeline (`docker-stack/otel-collector-config.yaml:41-44`) already writes to `otel_traces` with `create_schema: true`, so these attributes are captured automatically with no config change. Claudalytics does not yet build any view or dashboard on `otel_traces`; this is a forward-looking capability (e.g. correlating tool spans to conversations) rather than anything requiring action now.
