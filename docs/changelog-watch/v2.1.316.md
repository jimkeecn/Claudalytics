## Details

### 🟢 Low — Opus 4.8 fast-mode deprecation / Opus 5.5 migration vs. hardcoded latency panel

- **File:** `docker-stack/grafana/dashboards/otel-overview.json` — panel *"API Latency Percentiles per Model [KAN-22]"* (approx. line 913).
- **What the changelog says:** "Deprecated fast mode for Opus 4.8 as of October 30, 2026; it will be removed on November 30, 2026. … Migrate to Opus 5.5 to keep the speedup."
- **Why it matters:** The KAN-22 panel computes p50/p95/p99 with `quantileIf(..., LogAttributes['model']='claude-opus-4-6')` and `...='claude-haiku-4-5-20251001'` — model strings hardcoded into the SQL. As fleets move to **Opus 5.5** (`claude-opus-5-5`), their API latency will not appear in this panel. This is a **pre-existing hardcode** (the panel already predates Opus 4.8), but this release's explicit push to Opus 5.5 makes the staleness newly relevant.
- **Scope / blast radius:** Display-only. Raw `api_request` rows are still ingested, and the generic "Model Usage" panel (`SELECT LogAttributes['model'] … GROUP BY model`) and the subagent/model panels remain correct — they read `model` dynamically. No materialized view, target table, or ingestion path is affected; no data is lost.
- **Not a Break:** Ingestion and all MVs (003 credential, 005 file_mutations, 007 blocked_tools, 011 websites_visited) key off `event.name`, tool names, and attribute keys — none of which changed.
