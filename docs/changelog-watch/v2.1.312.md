# [CC Changelog] v2.1.312 — no impact

**v2.1.312 — no impact**

- Source: https://code.claude.com/docs/en/changelog (version 2.1.312, released 2026-10-27)
- Scan date: 2026-10-28
- Overall impact: 🟢 Low (no action required)

## Summary

No change in this release touches any hook event name, hook payload field, native
OpenTelemetry log/metric name, tool name, OTel env var, or health-check schema that
Claudalytics depends on. Ingestion (`hook-events.ts`, `field-mapping.ts`), the
ClickHouse materialized views, the Grafana dashboards, the OTel collector config, and
the plugin were all checked and are unaffected.

The three OTel-related changes in this release were reviewed specifically and confirmed
to concern native attributes/events the repo does **not** consume:

- **`claude_code.safety_event` OTel event stopped** — no repo query, MV, or dashboard
  references this event. Claudalytics does its own credential/safety detection in
  `clickhouse/init/003_credential_exposures_mv.sql` from `hooks.PostToolUse` Read paths,
  not from the native safety event. No impact.
- **`mcp_server.name` now reports the real name (instead of `custom`) for marketplace
  plugins' fixed-URL remote MCP servers** — the dashboard's "MCP Server Calls" panel reads
  `mcp_server_name` out of the `tool_parameters` JSON on native `tool_result`/`tool_decision`
  logs, not the top-level `mcp_server.name` attribute. No break; at most it means more
  accurate server names surface transparently.
- **`effort` OTel values fix (now show the level in force)** — no repo query, MV, or
  dashboard references the `effort` attribute. No impact.

Also noted (no action): the hook concurrency cap change ("prompt and agent hooks run at
most 24 at a time per session") throttles hook execution under heavy parallel/subagent
load but changes no schema; `plugin/hooks/forward-hook.sh` is a fast POST and the plugin's
forward hooks set no custom `timeout`. New env vars (`CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT`,
`CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK`) and `oidc.user_id_claim` are unrelated to the
telemetry env vars the repo sets.

No files changed beyond this audit-trail record.
