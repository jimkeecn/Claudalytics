### Details

#### 🟢 `git_commit_id` on OTel `tool_result` events (Improvement, Low)

- **Upstream change:** *"Fixed OpenTelemetry `tool_result` events missing `git_commit_id` after `git commit -q` or `git -C <dir> commit`."* The attribute previously dropped for those two common invocation styles and now populates consistently.
- **Current repo state:** A grep for `git_commit_id` / `git_commit` / `commit_id` across the entire repo returns **no matches**. Commit analytics rely solely on the native OTel metric `claude_code.commit.count` (see `docker-stack/grafana/dashboards/otel-overview.json`, "Commits vs Cost per Day [KAN-31]", which reads `otel_metrics_sum` where `MetricName = 'claude_code.commit.count'`). That metric is an aggregate count with no linkage to the specific commit SHA or the tool call that created it.
- **Why it's only Low / optional:** Nothing breaks. This is purely an opportunity to enrich data now that the attribute is trustworthy. The field flows into `claudalytics.otel_logs` already (it's part of Claude Code's native OTel `tool_result` log), so adoption is a dashboard/MV addition, not an ingestion fix.
- **Possible adoption path:** Optionally capture `git_commit_id` in the Bash `PostToolUse` branch of `field-mapping.ts` (alongside the existing `bash_urls` extraction) if the hook payload carries it, **or** add a ClickHouse view/panel over `otel_logs` filtering `LogAttributes['event.name'] = 'tool_result'` and grouping by `LogAttributes['git_commit_id']` to drive a per-commit leaderboard. No change is required to keep current behaviour correct.

#### 🟢 Sonnet 5.5 cache-read pricing change (Info, Low — no action)

- **Upstream change:** cache-read tokens for Sonnet 5.5 are now priced at $0.10/M (was $0.20/M).
- **Why the repo is safe:** The repo contains **no per-model or per-token pricing table** (grep for pricing/`per million`/`0.20`/`0.10` finds only dashboard `cost_usd` reads and the `agent.cache_read_tokens` passthrough in `field-mapping.ts`). All cost figures come from Claude Code's pre-computed `cost_usd` attribute, so the price change is reflected automatically with zero repo changes. This is the designed-for behaviour — recorded as a deliberate confirmation rather than a to-do.
