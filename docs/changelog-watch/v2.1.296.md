## Details

### 🟢 git_commit_id now reliable on native OTel `tool_result` events (Improvement, Low)

The changelog fixes a bug where native OpenTelemetry `tool_result` events dropped `git_commit_id` after `git commit -q` or `git -C <dir> commit`.

- **Current state:** The hooks-server tracks tool usage via `hooks.PostToolUse` (`docker-stack/hooks-server/src/field-mapping.ts`), not via native `tool_result` OTel logs. A grep for `git_commit_id` / `gitCommit` / `commit_id` across the repo returns **no matches**, so nothing breaks.
- **Opportunity:** Because the repo already ingests Claude Code's native OTel logs (that is where `cost_usd` and token counts come from — see `docker-stack/grafana/dashboards/otel-overview.json`), the `git_commit_id` attribute is now present and dependable on those `tool_result` logs. A future MV or dashboard panel could correlate tool/file activity to the commit it landed in.
- **Action required now:** None. This is an optional enhancement, not a fix.

### 🟢 Sonnet 5.5 cache-read repricing — dashboard data-interpretation note (Info, Low)

Sonnet 5.5 cache reads were repriced from $0.20 to $0.10 per million tokens in `/cost`, the status line, `--max-budget-usd`, and the SDK's cost figures.

- **Why it matters for Claudalytics:** `cost_usd` is emitted by Claude Code's OTel SDK and stored verbatim in `claudalytics.otel_logs` — the repo hardcodes **no** pricing table (grep confirms: pricing appears only as values flowing through, e.g. `otel-overview.json:448` `sum(toFloat64OrZero(LogAttributes['cost_usd']))`). So newly-ingested data automatically reflects the lower price.
- **Observable effect:** The **"$ per 1K Output Tokens [KAN-38]"** panel (`otel-overview.json:161`), whose own description says it "tracks cache efficiency and pricing drift", and the **"Cache Hit-Rate Trend [KAN-25]"** panel (`otel-overview.json:834`) will show a downward step for cache-heavy Sonnet 5.5 workloads starting from the upgrade date. This is a pricing change, not an efficiency regression — do not misread it as a usage anomaly when reviewing historical-vs-current cost trends.
- **Action required now:** None (no code change). Optionally add a dashboard annotation at the upgrade date so the step-change is self-explanatory.
